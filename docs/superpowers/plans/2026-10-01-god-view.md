# God View Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Give pilot admins a working web map of connected app users.

**Architecture:** Express serves the dashboard and a protected snapshot API.
The snapshot combines authenticated socket presence with measured GPS and ride
status. The mobile app publishes GPS only while signed in and foregrounded.

**Tech Stack:** Existing Express/Mongoose/auth, plain browser modules, MapLibre GL JS.

**Spec:** `docs/superpowers/specs/2026-10-01-god-view-design.md`

## Global constraints

- General Trias, 30-second GPS freshness, 3-second dashboard refresh.
- Existing account login; server-only `GOD_VIEW_ADMIN_PHONES`; deny by default.
- Dashboard access does not create mobile presence or change availability.
- Retain private ride event authorization and existing matching policies.

## Review focus

- A second socket must preserve presence when the first disconnects.
- Stale fixes, no GPS and failed refreshes must not appear live.
- Slow responses after logout must not restore dashboard or mobile data.
- Account fields containing markup must render as text.
- Older clients and drivers marked unavailable still need accurate labels.

## Execution notes

user's existing start scripts. No remote deployment or real admin grant is
implied. Use the requested account login; leave admin configuration disabled
unless the user supplies an account. No commits or worktree changes are needed
to make the implementation reviewable.
